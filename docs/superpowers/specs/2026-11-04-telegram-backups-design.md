# Ежедневные бэкапы в Telegram

## Цель

Раз в день создавать полный бэкап PostgreSQL и медиа MinIO, отправлять его владельцу в Telegram тем же ботом, что и заявки, и удалять локальные файлы после успешной доставки. Это внешняя копия на случай потери сервера, а не только локальная ротация дампов.

## Решения и границы

- Новый сервис `backup` запускается вместе с обоими вариантами стека; расписание по умолчанию — `30 3 * * *`, часовой пояс — `Europe/Moscow`.
- Сервис сам выполняет `pg_dump` и `mc mirror`, без Docker socket и без изменений приложения. Доступ нужен только к PostgreSQL, MinIO, Telegram и папке `VOLUMES_DIR/backups`.
- Один `.tar.gz` содержит `db_<дата>.dump` и `media/`, поэтому существующий `deploy/restore.sh` работает после распаковки без изменений.
- Файлы больше 45 МиБ делятся на нумерованные части перед `sendDocument`. Локальная копия удаляется только после ответа Telegram с `ok: true` для каждой части.
- При ошибке архив остаётся в `VOLUMES_DIR/backups/pending`; уже подтверждённые части отмечаются, чтобы не отправлять их повторно. На следующем запуске сначала отправляются накопленные архивы. Новый ежедневный архив всё равно создаётся.
- `TELEGRAM_DRY_RUN=1` запрещает сетевую отправку и удаление. Отсутствие токена или chat id считается ошибкой задачи, но не мешает запуску остального сайта.
- Ручной запуск: `docker compose run --rm backup /opt/gadyuka-backup/backup-now.sh`. Локальный `deploy/backup.sh` с его 14-дневной ротацией остаётся доступным отдельным механизмом.
- Не добавляются административный UI, отдельный Telegram-бот, шифрование архива и автоматическое удаление неотправленных копий.

## Подходы

1. **Отдельный контейнер — выбран.** Соответствует текущему Docker-развёртыванию, изолирует инфраструктурную задачу и не требует cron на хосте. Плата — небольшой Dockerfile и shell-скрипты.
2. **Cron на хосте + существующий `backup.sh`.** Меньше кода, но требует ручной настройки хоста и смешивает старое локальное зеркало с новым одноразовым архивом.
3. **Планировщик в NestJS.** Переиспользовал бы Telegram-модуль, но добавил бы инфраструктурные зависимости в приложение и потребовал бы доступа к `pg_dump` и новым пакетам; отклонён.

## Безопасность и эксплуатация

В архиве есть персональные данные заявок. Папка на хосте имеет режим `700`, контейнер работает без capabilities и `no-new-privileges`, токен не пишется в логи. Сеть `data` даёт доступ к хранилищам, `edge` — к Telegram. Отсутствие автоматического удаления неотправленных архивов означает, что при длительной ошибке нужно следить за местом на диске по логам `backup`.

## Принятые по умолчанию решения

В автоматическом режиме без дополнительных вопросов выбраны: полный бэкап базы и медиа, время 03:30 по Москве, порог частей 45 МиБ, хранение неотправленных файлов без срока давности и сохранение прежнего ручного сценария восстановления.
